## Addon import (app/)

After building the napi addon (`cd native && bun install && bun run build`, which enables the `napi-addon` Cargo feature), the UI imports:

```ts
import { pickFile, list, open, close, on } from '../native'
```

W3 wires call sites. W1 only documents the path (`app/app.tsx` comment and `app/native-addon.ts`); the hello window does not `import` the addon at runtime so `bun run dev` still works without a built `.node`.

`RGUI_FAKE=1` lets `open` accept any path and serve the fake catalog (needed so W3 can use the file picker). `policy: 'memory'` is rejected unless `RGUI_FAKE=1`, `NativeApp::for_test()`, or `native --self-test`. `NativeApp::new()` during `cargo test` still rejects `memory` unless `RGUI_FAKE=1`.

W1 addon commands are synchronous (see [05-napi-contract.md](../../architecture/05-napi-contract.md)). `DirPage.nextCursor` / `totalHint` / `DirEnt.mtime` are JS `null` when absent (not a missing property).
